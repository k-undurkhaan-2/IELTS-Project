# IELTMPS Project

**交互式英语语言测试模拟练习系统（Interactive English Language Test Mock Practice System）**

[English](README.md) | [简体中文](README.zh-CN.md)

`IELTS-Project` 维护由服务器支撑的一体化 IELTMPS Web Service，用于基于计算机的英语语言测试模拟练习。

本仓库负责 IELTMPS Server、生产 Web UI、Server/客户端集成、数据与多设备服务、容器化部署和发布，以及该一体化服务所需的治理。项目面向公益服务团队和独立自托管运营者。由维护者运营的 Hosted Service 仍属于**有条件的方向（Conditional）**。

## 关于 IELTMPS

一体化 Web Service 将生产环境使用的 IELTMPS Web Client 与 IELTMPS Server 结合。Web Client 提供基于浏览器的阅读、听力、模拟练习、账户、记录、统计和数据管理体验。Server 提供由 PostgreSQL 支撑的身份验证、会话、记录、管理和受保护资源功能。

生产 Web UI 仍由本仓库负责，包括 Business、Auth 和 Admin UI，账户与安全交互体验，由服务器支撑的练习，历史记录与统计，设置与数据界面，多设备状态呈现，响应式与无障碍工作，Server 契约集成，以及生产前端构建产物。

通用上游客户端/UI 开发、独立运行或纯静态客户端、无关的本地应用，以及服务商特定、私有或本地 AI 应用，均已被界定为长期仓库职责之外的**外部化工作（Externalized）**。本仓库仍可采用上游修订、集成修复、适配源自上游的前端代码、保持兼容性，并实现服务专用 UI。外部化不意味着移除当前的一体化前端，也不意味着移除服务所需的集成工作。

未来可能出现其他仓库，也可能考虑建立专门的 IELTMPS 组织。目前尚未建立此类组织，本文也不假定外部仓库或替代应用已经存在。

当前交付的界面和若干兼容性标识仍包含历史上的 IELTS Atlas 或 IELTS Practice 名称。本轮文档工作不会机械替换这些名称。运行时品牌、包名、容器与数据库标识、浏览器存储键、发布产物和测试需要另行规划兼容性迁移。

## 使命

IELTMPS 希望让公益服务团队和自托管用户更容易获得严肃、基于计算机的英语语言测试练习工具。项目倾向于由服务器辅助的体验，使账户、受保护资源、持久记录，以及最终具有权威性的结果处理能够在多设备间得到一致管理。

项目也明确区分公开源代码、单独获得授权的运行时内容，以及部署密钥等敏感信息。源代码公开不代表有权再分发所有随附或本地提供的学习资源。可持续的服务必须同时尊重开源义务与教育内容所附带的权利。

## Hosted Service 与部署模式

IELTMPS 区分由维护者运营的服务和由第三方独立自托管的服务。

**IELTMPS Hosted Service** 属于**有条件的方向（Conditional）**。[服务模式](docs/SERVICE_MODEL.md)和[状态文档](docs/STATUS.md)说明了其公益导向、计划仅通过 Tor 提供的业务访问、资金边界和就绪限制。权利与来源及内容审查、安全审查、条款/隐私/可接受使用政策、监控、事件与滥用处理、恢复、升级与回滚、支持范围和运营能力，都必须为单独的就绪与上线决策提供依据。目前既未确立公共服务已上线的事实，也未安排上线时间。

**第三方自托管部署**由其他个人或组织独立运营。自托管运营者负责基础设施安全、合法内容、用户支持、隐私说明、备份、滥用处理，以及遵守适用的软件和内容许可证。项目计划中的服务政策不会自动适用于第三方部署，也不表示项目对其作出认可。

Docker/容器化部署是计划长期支持的应用部署模式，Docker Compose 是当前仓库中已有的起点。直接运行的非 Docker 应用部署路径仍然存在，但属于**计划弃用**的范围。文件/静态/独立运行模式仍是当前的过渡能力，处于**计划解耦**阶段。实际移除或撤回支持需要另行授权的迁移与验收；正常的开发和测试工具仍可在容器之外运行。

## 通过 Tor 访问

有条件的维护者运营服务计划通过 Tor 网络开放公共业务层。项目推荐 Tor Browser，并计划在 Hosted Service 上线的条件下为其提供支持。业务 onion 地址尚未发布，也不作保证；公开的明网 Hosted Service 端点既未发布，也不在当前承诺之列。

其他支持 Tor 的浏览器、扩展、代理和集成不受支持。它们的行为可能不同，也不被视为在隐私保护方面等同于 Tor Browser。如果未来发布地址，用户应通过签名的发布公告和另一个由维护者控制的可信渠道进行核验。详见 [Tor 访问](docs/TOR_ACCESS.md)。

## 架构概览

当前架构将大量浏览器端练习逻辑与服务器支撑的能力结合。Web Client 使用生成的构建产物、浏览器存储、本地数据源和本地回退路径。经过身份验证的操作可使用 Server 处理账户和由 PostgreSQL 支撑的练习记录。受保护的运行时资源在公开源代码树之外单独提供。

仓库中的部署配置区分业务、管理和身份验证服务，并包含通过 Tor 暴露服务的配置，但实际生产运行尚未得到验证。已批准的方向是将持久状态和权威评分等更多涉及信任的行为迁移到 Server；这并不表示迁移已经完成。

稳定的 Server/客户端集成契约，以及由 Server 负责的数据与多设备语义，是核心架构目标；这不代表版本化的公开契约产物或完整的同步行为已经存在。针对特定服务商的 AI 应用属于外部化工作。本仓库仅在适用时保留通用 Server 互操作性、安全、授权、隐私与数据提供边界，以及契约所需的速率/配额边界。详见[架构概览](docs/ARCHITECTURE.md)。

## 开始使用

一体化服务当前在仓库中已有的起点是 Docker Compose。在仓库根目录，根据受版本控制的示例创建本地后端环境文件，检查所有必填占位项，然后启动仓库中的 Compose 配置：

```powershell
Copy-Item backend\.env.example backend\.env
docker compose --env-file backend\.env -f backend\docker-compose.yml up --build
```

不要提交生成的环境文件，也不要在对外暴露的部署中复用示例或开发凭据。

这些命令是开发和自托管的起点，不是完整的生产安全操作流程。面向互联网或 onion 服务的运行需要单独开展安全审查，覆盖密钥等敏感信息、内容授权、反向代理行为、备份、监控、事件响应和访问边界。

当前代码仍支持文件/静态运行、本地存储与回退，以及直接运行路径。文件/静态/独立运行的解耦和非 Docker 应用部署的弃用属于计划，尚未发生移除。任何移除或支持撤回都需要单独的运行时迁移、兼容性与数据保全计划，以及验收。当前运行模式见[使用指南](docs/USAGE.md)；容器外的正常工具使用见[开发指南](docs/DEVELOPMENT.md)。

软件许可证不会自动涵盖考试试题、文章、音频、PDF、图片、解析、字体、词典、标志、商标或单独提供的练习资源。公共服务运营者和自托管用户必须具备独立的法律依据，才能使用和分发其内容。

IELTS 相关名称和标志归各自的所有者所有。IELTMPS 必须保持明确的独立性，避免使用官方品牌，也不得将练习结果表述为经过认证的考试成绩。仓库尚未完成对所有现有内容类别的完整权利清单。详见[内容政策](docs/CONTENT_POLICY.md)。
